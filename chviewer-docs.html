ClickHouse Viewer: полигоны и сетка H3 на карте

Один exe-файл под Windows поднимает локальный сервер, открывает браузер и рисует мультиполигоны из любых таблиц ClickHouse на карте OpenStreetMap — на GPU, с кэшем на бэке, фильтром детализации и сеткой гексагонов H3.

1Архитектура

Приложение состоит из двух частей, упакованных в один файл chviewer.exe (Go, ~8 МБ, статическая сборка): микро-бэкенда и веб-страницы, вшитой в бинарник. Бэкенд слушает только 127.0.0.1:8137 и выполняет три роли: отдаёт страницу, хранит настройки в config.json рядом с exe и проксирует запросы к ClickHouse.

Такое разделение решает три проблемы, которые убивают вариант «просто HTML-страница»:

  • CORS — браузер запрещает запросы к другому хосту; локальный прокси снимает это полностью;
  • самоподписанный SSL — браузер молча блокирует такой сертификат, а Go-клиент умеет InsecureSkipVerify по галочке «не проверять сертификат»;
  • кэш — повторные заходы в уже просмотренную область не порождают запросов к БД вообще.

2Запуск и настройка

  1. Запустите chviewer.exe — поднимется сервер и откроется браузер (флаг -nobrowser отключает автоматическое открытие).
  2. В панели укажите Сервер — достаточно IP или имени хоста: протокол и порт подставятся из галочки SSL (https://…:8443 или http://…:8123); явно указанные протокол/порт не перезаписываются.
  3. Логин и пароль ClickHouse, список слоёв — и «Подключиться».
  4. «Сохранить настройки» пишет всё в config.json; при следующем запуске страница сама восстановит слои и подключится.

3Слои

Слой — это таблица ClickHouse с колонкой типа MultiPolygon. Структура таблицы не фиксирована: при подключении выполняется DESCRIBE TABLE, и все остальные колонки автоматически становятся атрибутами объекта (их показывает попап). У каждого слоя:

  • галочка видимости — скрытый слой не рисуется и, главное, не запрашивается из БД;
  • цвет — выбирается автоматически из палитры, меняется кликом по квадратику;
  • таблица и имя колонки с полигонами;
  • порядок — перетаскивание за ручку слева или стрелки ↑/↓; первый в списке — верхний на карте.

Сетка H3 — тоже слой: участвует в том же списке и в том же порядке, но вместо таблицы у неё разрешение (авто или 5–11), толщина линий и цвет.

4Загрузка данных: только то, что видно

Главный принцип: из БД читается только видимая область, и только объекты, различимые на текущем масштабе. При каждом сдвиге или зуме карты (после паузы 300 мс, чтобы не стрелять на каждое движение) фронтенд шлёт на exe запрос /api/objects с рамкой экрана.

Границы объекта считаются прямо в SQL из координат мультиполигона — работает на любой таблице без предварительной подготовки:

WITH flatten(flatten(`key`)) AS pts,
     arrayMap(p -> p.1, pts) AS xs,
     arrayMap(p -> p.2, pts) AS ys
SELECT *, cityHash64(toString(`key`)) AS __id
FROM emr_ch.tbl_polygons_bmt
WHERE arrayMin(xs) <= 37.9 AND arrayMax(xs) >= 37.4     -- пересечение с экраном
  AND arrayMin(ys) <= 56.0 AND arrayMax(ys) >= 55.6
  AND NOT (…)                                            -- минус покрытые территории
  AND (arrayMax(xs)-arrayMin(xs) >= 0.0012 OR …)         -- минус слишком мелкие
LIMIT 30000
FORMAT JSON
Координаты MultiPolygon в FORMAT JSON приходят готовыми вложенными массивами [долгота, широта] — они без преобразований подставляются в GeoJSON. Идентификатором объекта служит cityHash64 от геометрии, поэтому таблице не нужна колонка-ключ.

5Кэш территорий на бэке

Кэш живёт в памяти exe отдельно для каждого слоя (ключ — сервер + пользователь + таблица + колонка). Хранятся две вещи:

  • объекты — по хэшу геометрии, с посчитанным bbox;
  • покрытые территории — прямоугольники, для которых выборка была полной (лимит не отрезал хвост), вместе с уровнем детализации, на котором их грузили.

Исключение уже загруженного из повторных запросов делается территориями, а не списками идентификаторов: в SQL добавляется по одному условию AND NOT (объект пересекает прямоугольник) на каждую покрытую область (их не больше 64), а не NOT IN с тысячами значений. Это корректно, потому что объект, пересекающий полностью загруженную область, гарантированно уже в кэше.

Запрос к БД идёт с запасом +30 % вокруг экрана — мелкие сдвиги карты вообще не порождают обращений. Кнопка «Подключиться» сбрасывает кэш.

6Фильтр детализации: мелкое не грузим

Тысячи «домиков» размером меньше пикселя не имеют смысла на обзорном масштабе — они только перегружают сеть и рендер. Фронтенд считает, сколько градусов занимают 3 пикселя на текущем зуме, и передаёт это число (min_deg) с каждым запросом. Бэкенд добавляет в SQL условие «ширина или высота объекта не меньше порога» — мелочь не читается из БД вовсе.

Чтобы это дружило с кэшем, каждая покрытая территория помнит детализацию, с которой её грузили. Область, покрытая «грубо», не считается покрытой для более детального запроса — поэтому при приближении мелкие объекты честно дочитываются из БД, а повторный просмотр на том же зуме идёт из кэша.

7Сетка H3

Слой сетки использует компонент react-h3-map (без React-обёртки — напрямую его WebGL-слой H3GridLayer и модуль геометрии). Ячейки не приходят из БД — они вычисляются из рамки экрана функцией polygonToCells, вся сетка рисуется одним draw call.

  • Разрешение — «авто» (подбирается по зуму так, чтобы ребро было ~40 px) или фиксированное 5–11. Пункты, дающие больше 60 000 ячеек на текущем масштабе, автоматически гаснут с пометкой «приблизьте карту» и обновляются при каждом движении.
  • Предохранитель — прежде чем строить сетку, дешёвой арифметикой оценивается число ячеек; выше лимита сетка не строится (иначе вкладка зависла бы на минуты).
  • Клик по ячейке показывает индекс в двух видах: hex (8711aa636ffffff) и int64 (608296725861367807) — второй удобен для join-ов в ClickHouse, где H3-индексы обычно лежат как UInt64.
  • Ячейка под курсором подсвечивается янтарным контуром; определяется за O(1) через latLngToCell — без пикинг-рендера.

8Наведение и клики: верхний объект побеждает

И подсветка, и попап работают по одному правилу: реагирует самый верхний объект под курсором с учётом порядка слоёв в панели.

Попап объекта показывает все колонки таблицы, кроме геометрии: числа с разделителями разрядов, булевы — «да/нет», пустые — прочерк, вложенные структуры — моноширинным. Высота попапа ограничена половиной экрана: если полей много, внутри появляется прокрутка, за край окна он не вылезает. Подсветка полигонов сделана через feature-state MapLibre — состояние меняется на GPU без перестроения геометрии.

9Шифрование пароля

Пароль ClickHouse нигде не хранится открытым текстом. В config.json попадает только шифртекст, а ключ выводится из отпечатка браузера — на другой машине или в другом браузере файл бесполезен, страница попросит ввести пароль заново.

В лог пароль не попадает никогда. Но помните: пользователь ClickHouse для просмотрщика лучше заводить read-only с доступом только к нужным таблицам.

10Отладка

  • Консоль exe — развёрнутый лог: каждый запрос (адрес, пользователь, SSL, полный SQL), результат (HTTP 200, 89246 байт за 23ms), состояние кэша, полные тексты ошибок ClickHouse.
  • Ссылка SQL в статусе — последний запрос в том виде, в каком он ушёл на сервер; кнопка «Скопировать SQL» позволяет выполнить его напрямую в clickhouse-client.
  • При ошибке окно с SQL открывается само и показывает полный текст ошибки сервера рядом с запросом.
